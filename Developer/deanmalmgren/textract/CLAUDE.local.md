# CLAUDE.local.md

Guidance for AI agents working in this repo. This is a supplement to `docs/contributing.rst`, which has the full human-facing walkthrough for adding a new file type — read that first for the step-by-step. This file covers the nuances that are easy to miss.

## Architecture in one paragraph

`textract.parsers.process()` maps a file extension to a module named `textract/parsers/<ext>_parser.py` via `importlib` — there is no registry to update. Each module defines a `Parser` class implementing `extract(self, filename, **kwargs) -> bytes | str`, subclassing `BaseParser` (pure Python) or `ShellParser` (shells out to an external binary) from `textract/parsers/utils.py`. `BaseParser.process()` wraps `extract()` in a "unicode sandwich": decode with `chardet` (or an explicit `input_encoding`), then re-encode to `output_encoding`. Don't duplicate that decode/encode logic in a new parser.

Extension aliasing (`.htm` -> `.html`, `.jpeg` -> `.jpg`, etc.) lives in `EXTENSION_SYNONYMS` in `textract/parsers/__init__.py`, not in the parser itself.

## Adding a new file type

1. `textract/parsers/<ext>_parser.py` — new `Parser` class, auto-discovered purely by filename; no other file needs to know it exists.
1. Test fixtures live in `tests/<ext>/`. For pure-Python parsers, generate the expected output by actually running the parser and committing the result:
    ```
    textract tests/<ext>/raw_text.<ext> > tests/<ext>/raw_text.txt
    ```
    Don't hand-write expected output — different libraries format numbers, whitespace, and empty cells differently than you'd guess.
1. For parsers backed by an external CLI tool (OCR, PostScript, etc.), add fixture rules to `tests/Makefile` instead — those `.txt` files are generated by the real tool and committed so CI doesn't need the tool installed for most runs.
1. `tests/test_<ext>.py` is almost always just:
    ```python
    class ExtTestCase(base.BaseParserTestCase, unittest.TestCase):
        extension = "ext"
    ```
    `base.BaseParserTestCase` (in `tests/base.py`) supplies the raw/CLI/ standardized test methods; don't reimplement them.
1. If the format needs a new dependency, add it to `pyproject.toml` `dependencies` with an inline `#` comment explaining *why* (see the `openpyxl`/`xlrd`/`odfpy` cluster there — each comment states what the library is for and why it coexists with its neighbors rather than replacing them).
1. Document the new extension in `docs/index.rst`'s bullet list.
1. **Update `docs/changelog.rst`** under `NEXT RELEASE`. CI's `changelog-check` job fails any PR that touches `textract/**/*.py` without a corresponding `docs/changelog.rst` edit — this is enforced, not just a convention.

## Warnings from third-party libraries

Don't reflexively silence a warning by category. Read where it's raised first:

- If it points at something you can fix at the call site (e.g. an ambiguous parser mode, a soon-removed argument), fix that instead of filtering it.
- If it's inherent to the input data (e.g. openpyxl warning about an OOXML extension it intentionally drops), the precise fix is a narrow, message-scoped entry in `[tool.pytest.ini_options].filterwarnings` in `pyproject.toml`, not a blanket `ignore::UserWarning`. Check whether the library defines a dedicated warning subclass to filter on before falling back to matching the message text.

## Optional system dependencies (LibreOffice, tesseract, etc.)

Some parsers (`.doc` via LibreOffice, image/PDF OCR via tesseract) shell out to a binary that isn't a Python dependency. Follow the `doc_parser.py` pattern: probe multiple likely binary locations/names via `shutil.which` plus known install paths, raise a specific `CommandLineError` subclass from `textract/exceptions.py` with actionable install instructions if the binary is missing, and don't let the whole test suite hard-fail when it's absent locally.

`.github/actions/setup/action.yml` installs these binaries unconditionally for every OS in the matrix, so a new binary dependency has to be added there for Linux, macOS, and Windows. Windows is where it usually breaks: the installer drops the exe somewhere that isn't on PATH, so the step has to append the directory to `$GITHUB_PATH` itself. That file carries inline comments explaining each deviation from the plain install path; read them before consolidating steps that look redundant.

Binary lookup must also survive freezing. `tests/freeze/smoke_test.py` (CI job `cx-freeze`) builds a cx_Freeze executable and runs it against fixtures covering both pure-Python and shell-based parsers, guarding the `importlib`-routed parser discovery and the PATH lookups shell parsers depend on. Add a sample there when a new parser exercises a mechanism the existing samples don't.

## Two things that must move together

- `pyproject.toml` (`version`) and `textract/__init__.py` (`VERSION`) — use `python scripts/bump_version.py <version>` rather than editing both by hand.
- `requires-python` in `pyproject.toml` and `target-version` under `[tool.ruff]` state the same floor and must be bumped together. That floor is enforced, not aspirational: the CI matrix in `.github/workflows/ci_pipeline.yml` tests it alongside the newest supported Python, on macOS, Ubuntu, and Windows. Read the floor from `pyproject.toml` and write for it, even though the dev venv runs a newer interpreter, and don't assume POSIX paths or POSIX-only binaries.

## Checks before calling something done

```
make check     # ruff check + pyright + pytest
make fix       # ruff format + ruff check
```

`ruff` runs a deliberately narrow `select` (see `[tool.ruff.lint]` in `pyproject.toml`) rather than the full default rule set, so style patterns other ruff configs would flag pass silently here. Match the surrounding code instead of relying on the linter to catch style.
